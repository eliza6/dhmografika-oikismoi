# Δημογραφικά Οικισμών — Απογραφή 2021 (ΕΛΣΤΑΤ)

Web εφαρμογή που δείχνει, για οποιονδήποτε οικισμό της Ελλάδας: φύλο×ηλικία,
φύλο×εκπαίδευση, ηλικία×εκπαίδευση, έναν πλήρη 4D πίνακα φύλο×απασχόληση×
ηλικία×εκπαίδευση (με διαδοχική εξερεύνηση/drill-down), και αριθμό αυτοκινήτων
ανά νοικοκυριό. Αναζήτηση-autocomplete, πλοήγηση σε tabs σαν browser, και
toggle απόλυτων αριθμών/ποσοστών.

## Ρύθμιση (μία φορά)

```bash
pip install -r requirements.txt
python3 build_db.py
```

Το `build_db.py`:
1. Ελέγχει αν τα 7 πηγαία αρχεία της ΕΛΣΤΑΤ υπάρχουν ήδη στον φάκελο `data/`.
2. Αν όχι, τα κατεβάζει αυτόματα από το statistics.gr (χρειάζεται σύνδεση στο
   internet).
3. Τρέχει ολόκληρη την αλυσίδα IPF (βλ. παρακάτω) και χτίζει το
   `settlements.db` (SQLite) με όλους τους οικισμούς της χώρας. Παίρνει
   περίπου 3-4 λεπτά λόγω του 4D υπολογισμού.

Αν κάποιο αρχείο αλλάξει στο statistics.gr και θέλεις να το ξανακατεβάσεις:

```bash
python3 build_db.py --force
```

Αν η αυτόματη λήψη αποτύχει (π.χ. αλλαγή στο site της ΕΛΣΤΑΤ), το script σου
δίνει τον ακριβή σύνδεσμο και το path όπου πρέπει να αποθηκεύσεις το αρχείο
χειροκίνητα, ώστε να συνεχίσει κανονικά στο επόμενο τρέξιμο.

## Εκκίνηση

```bash
python3 app.py
```

Άνοιξε http://127.0.0.1:5050 στον browser.

## Πηγές δεδομένων

Σε επίπεδο **οικισμού** (πραγματικά στοιχεία):
- **Γ01** — μόνιμος πληθυσμός κατά φύλο και ηλικιακή ομάδα
- **Γ04** — μόνιμος πληθυσμός κατά φύλο και επίπεδο εκπαίδευσης

Σε επίπεδο **δήμου** (χρησιμοποιούνται ως seed για IPF):
- **Β02** — ηλικιακή ομάδα × επίπεδο εκπαίδευσης
- **Β01** — απασχόληση × ηλικιακή ομάδα
- **Β02 (employment)** — απασχόληση × φύλο
- **Β03** — απασχόληση × επίπεδο εκπαίδευσης

Σε επίπεδο **Δημοτικής Κοινότητας** (πραγματικά στοιχεία, κληρονομούνται
αναλλοίωτα από κάθε οικισμό της):
- **Γ13** — αριθμός αυτοκινήτων × νοικοκυριό

## Μεθοδολογία (IPF pipeline)

Η ΕΛΣΤΑΤ δεν δημοσιεύει κανέναν από αυτούς τους συνδυασμούς σε επίπεδο
οικισμού, οπότε ακολουθούμε μια αλυσίδα εκτιμήσεων:

1. **IPF#1 (age × education, οικισμός)** — seed: ο πίνακας του δήμου (Β02).
   Προσαρμόζεται ώστε γραμμές/στήλες να ταιριάζουν ταυτόχρονα με την
   πραγματική ηλικιακή (Γ01) και εκπαιδευτική (Γ04) κατανομή του οικισμού.
2. **IPF#2, #3, #4 (age×employment, gender×employment, education×employment,
   οικισμός)** — seed: οι αντίστοιχοι πίνακες του δήμου (Β01/Β02/Β03). Εδώ
   υπάρχει μόνο **ένα** πραγματικό marginal διαθέσιμο ανά οικισμό (δεν
   δημοσιεύεται κανένα σύνολο απασχόλησης ανά οικισμό), οπότε είναι
   αναλογική προσαρμογή σε αυτό το ένα marginal.
3. **4D IPF (gender × age × education × employment, οικισμός)** — γενικευμένη
   IPF ("raking") πάνω σε 4 διαστάσεις ταυτόχρονα, χρησιμοποιώντας και τους 6
   2D πίνακες παραπάνω (2 πραγματικούς + 4 εκτιμημένους) ως ταυτόχρονους
   περιορισμούς. Το αποτέλεσμα είναι η πλήρης κοινή κατανομή (joint
   probability distribution) — αυτό βλέπεις στο drill-down του πίνακα 4.

Επειδή τα ίδια τα δημοσιευμένα στοιχεία της ΕΛΣΤΑΤ έχουν μικρές, ανεξάρτητες
αποκλίσεις στρογγυλοποίησης μεταξύ διαφορετικών πινάκων (μέτρο προστασίας
απορρήτου/στατιστικού απορρήτου), το 4D IPF συγκλίνει σε έναν **βέλτιστο
συμβιβασμό** (residual σφάλμα τυπικά <1%) και όχι σε απόλυτα μηδενικό
σφάλμα — αυτό είναι αναμενόμενο, όχι σφάλμα του κώδικα.

Το UI δηλώνει καθαρά με ετικέτα ποιος πίνακας είναι εκτίμηση.

## Δομή αρχείων

```
build_db.py   ETL: κατεβάζει τα xlsx, τρέχει το IPF pipeline, χτίζει το settlements.db
app.py        Flask backend (αναζήτηση, δεδομένα οικισμού, drill-down API)
static/       Frontend (search bar, tabs, πίνακες, toggle, drill-down)
data/         (δημιουργείται αυτόματα) cache των κατεβασμένων xlsx
settlements.db (δημιουργείται αυτόματα από το build_db.py)
```
